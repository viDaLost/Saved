# Saved — Telegram Business-бот для выбранных медиа

Бот пересылает обычное фото, видео, аудио, голосовое сообщение, документ или кружочек в ваш личный чат с ботом **только когда вы сами ответили на это сообщение** в подключённом бизнес-чате. Достаточно свайпнуть входящее медиа для ответа и отправить любой текст. Входящие медиа без вашего ответа не пересылаются. Бот принимает действия только от Telegram ID владельца, указанного в `OWNER_ID`.

**Ограничение:** фото и видео «на один просмотр», исчезающие и защищённые сообщения не гарантируется получить через Telegram Bot API. Telegram может вообще не включить исходное сообщение в `reply_to_message`; бот не обходит эти ограничения. Медиа отдельно на диске сервера не сохраняются: бот пересылает доступный ему файл в ваш личный чат с ботом. Для доступа к нему вы должны предварительно открыть чат с ботом.

## Настройка в Telegram

1. Создайте бота в [@BotFather](https://t.me/BotFather) и получите токен. В настройках бота включите **Business Mode / Secretary Mode** (название в интерфейсе может отличаться).
2. Откройте личный чат с ботом и напишите `/start`.
3. В Telegram откройте **Настройки → Telegram Business → Чат-боты** и подключите созданного бота. Разрешите ему доступ к нужным чатам. Другим людям ваш токен не передавайте.

## Через App Platform с телефона (проще)

На телефоне в панели Timeweb Cloud выберите **App Platform** в левом меню (это отдельный раздел, не «Облачные серверы»). Для запуска используется `Dockerfile` из этого репозитория. Выделять отдельный сервер Ubuntu и вводить команды в его консоли не нужно.

1. Откройте **App Platform → Создать / Добавить**, выберите тип **Dockerfile**.
2. Подключите GitHub или укажите публичный URL `https://github.com/viDaLost/Saved`, выберите репозиторий **viDaLost/Saved**, ветку **main**. Проверьте, что фреймворк определён как **Dockerfile**, а путь к директории проекта пуст (Dockerfile лежит в корне).
3. Выберите регион и подходящую конфигурацию, **один экземпляр приложения**.
4. В **Расширенных настройках → Переменные** добавьте локальную переменную `BOT_TOKEN` со значением токена @BotFather. Если вы уже знаете свой числовой Telegram ID, добавьте `OWNER_ID` сразу; иначе после первого запуска отправьте боту `/id`, узнайте число и затем добавьте `OWNER_ID` через **Настройки → Настройка деплоя → Редактировать → Переменные**.
5. В поле **Путь проверки состояния** укажите `/health`. Dockerfile объявляет порт `8080`; бот отвечает на `/health` и `/`, а сообщения получает через опрос Telegram. Домен и webhook для Telegram настраивать не надо. Если деплой заканчивается ошибкой `unhealthy`, проверьте, что переменная `BOT_TOKEN` задана и в поле проверки указан `/health`, затем откройте логи приложения: причина завершения процесса видна там, а не всегда в журнале сборки.
6. Нажмите **Запустить деплой**. Проверьте статус и логи. После добавления `OWNER_ID` убедитесь, что новая конфигурация запущена; затем напишите боту `/start`, подключите его в Telegram Business и попробуйте ответить на обычное фото.

Токен вводите только в переменных App Platform; не размещайте его в репозитории, Dockerfile или скриншотах. Не запускайте одновременно вторую копию бота на облачном сервере: два процесса с одним токеном будут мешать друг другу при `getUpdates`.

## Развёртывание на облачном сервере Timeweb Cloud (Ubuntu)

В панели Timeweb Cloud создайте **облачный сервер** с Ubuntu и подключитесь к нему по SSH либо через веб-консоль сервера. Далее команды выполняются **на сервере**. Для этого проекта достаточно непрерывно работающего Python; Docker, домен, открытый HTTP-порт и платформа для сайтов не нужны.

### 1. Установить код

```bash
sudo apt update
sudo apt install -y git python3
sudo git clone https://github.com/viDaLost/Saved.git /opt/saved-bot
sudo useradd --system --home /opt/saved-bot --shell /usr/sbin/nologin savedbot
sudo chown -R root:root /opt/saved-bot
sudo chmod -R a+rX /opt/saved-bot
```

Если репозиторий приватный, на сервере нужен отдельный доступ к GitHub (например, deploy key); не вставляйте токен GitHub в URL репозитория. Если пользователь `savedbot` уже создан, пропустите команду `useradd`.

### 2. Добавить секреты

```bash
sudo install -m 600 -o root -g root /dev/null /etc/saved-bot.env
sudo nano /etc/saved-bot.env
```

В редакторе введите две строки, подставив **свой** токен BotFather:

```ini
BOT_TOKEN=ваш_токен_от_BotFather
OWNER_ID=
```

Пока `OWNER_ID` пуст, бот отвечает только на `/id`, чтобы вы узнали собственный числовой Telegram ID. Сохраните файл (`Ctrl+O`, `Enter`, `Ctrl+X`). Этот файл остаётся на сервере и **не добавляется в Git**.

### 3. Запустить службу и получить свой ID

```bash
sudo cp /opt/saved-bot/saved-bot.service /etc/systemd/system/saved-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now saved-bot
sudo systemctl status saved-bot --no-pager
```

Напишите боту в личном чате `/id`. Он ответит числом. Ещё раз откройте конфигурацию:

```bash
sudo nano /etc/saved-bot.env
```

Вставьте число после `OWNER_ID=`, например `OWNER_ID=123456789`, и перезапустите службу:

```bash
sudo systemctl restart saved-bot
sudo systemctl status saved-bot --no-pager
```

Теперь напишите боту `/start`, подключите его в Telegram Business и проверьте на обычном фото: попросите знакомого прислать вам фото в разрешённый чат, ответьте на него свайпом. Выбранное фото должно появиться в личном чате с ботом.

### Проверка и обновление

```bash
sudo journalctl -u saved-bot -n 50 --no-pager
sudo git -C /opt/saved-bot pull --ff-only
sudo systemctl restart saved-bot
```

Если `/id` не отвечает, проверьте статус службы и токен. Если медиа не приходит, проверьте `OWNER_ID`, доступ бота к нужному бизнес-чату и наличие исходного файла в ответе. Для `getUpdates` у бота не должен быть активен webhook; одновременно запускайте только **один** экземпляр этого бота. Токен бота и содержимое `/etc/saved-bot.env` никому не отправляйте.
